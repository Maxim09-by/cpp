# ember

Це навчальний проект на C++: модель пам'яті, побайтовий дамп, базовий ALU та простий CPU. Проект збирається як консольний застосунок і використовується для лабораторної роботи з представленням даних у пам'яті, бітовими операціями та простим виконанням інструкцій.

## Що реалізовано

- Lab 01: робота з `Memory`, адресацією, виведенням байта та дампом пам'яті
- Lab 02: ALU та CPU з флагами `Z`, `N`, `C` та командним інтерфейсом
- Lab 03: 16-бітні доступи little-endian, інструкції `LOAD`/`STORE`, адресний регістр `H`, `OUT`/`OUTN` і команда `run`

### Lab 03: адреси та адресний регістр

Запис 16-бітного значення використовує little-endian:

```text
mem_set16(mem, 0, 0x1234)
0x00 = 0x34, 0x01 = 0x12
```

Приклад програми через `H`:

```text
0x28 0x00 0x08  LOADH H, 0x0800
0x29              LOAD A, [H]
0x02              OUT
0x2B              INCH
0x29              LOAD A, [H]
0x02              OUT
0x00              HALT
```

За байтами `65 66` в пам'яті за адресою `0x0800` програма друкує `AB`, а `H` стає рівним `0x0801`.

У C++ `Memory* mem` у CPU — це вказівник хоста на весь масив. `pc` і `h` — цілі адреси гостя всередині цього масиву. Зберігати адресою гостя вказівник хоста небезпечно: машинна адреса об'єкта має іншу ширину й значення й не переноситься в інші процеси.

## `sizeof` на цій машині

| Type | `sizeof` | Коментар |
|---|---:|---|
| `char` | 1 | byte |
| `bool` | 1 | boolean |
| `short` | 2 | 16-bit |
| `int` | 4 | signed int |
| `long` | 8 | 64-bit |
| `long long` | 8 | 64-bit |
| `float` | 4 | 32-bit float |
| `double` | 8 | 64-bit double |
| `void*` | 8 | pointer |
| `std::uint8_t` | 1 | exact byte |
| `std::uint16_t` | 2 | exact 2 bytes |
| `std::uint32_t` | 4 | exact 4 bytes |
| `std::size_t` | 8 | size/count type |

## Важливі деталі реалізації

- `Memory` зберігає масив `Byte data[MEM_SIZE]{}` і ініціалізується нулями.
- Адреси валідні від `0` до `MEM_SIZE - 1`.
- `mem_get` та `mem_set` не дозволяють виходити за межі масиву.
- `dump` друкує пам'ять рядками по 16 байт.
- `show_byte` показує одне і те саме значення у 4 формах: число, hex, binary, символ.
- ALU повертає результат і флаги: `z`, `n`, `c`.
- CPU зберігає `pc`, регістри `a`/`b`, флаги та стан `halted`.

## Примітки

- Проєкт збирається з `-Wall -Wextra -Werror`.
- У режимі Debug додані ASan і UBSan.
- Для навчальної задачі важливо не просто “щоб працювало”, а щоб структура відповідала ідеї пам'ять + ALU + CPU і була зрозумілою в коді.

## ASan: вихід за межі масиву

Навмисне звернення `mem.data[4096]` при розмірі масиву `4096` викликало звіт:

```text
AddressSanitizer: stack-buffer-overflow
WRITE of size 1
    at offset 4128 in frame
SUMMARY: AddressSanitizer: stack-buffer-overflow ... in main
```

Звіт показав, що це запис поза останньою адресою `4095`. Виправлення — перевіряти `addr >= MEM_SIZE` до `mem.data[addr]`; у VM адреси читання двохбайтового інструкційного операнда перевіряються теж до читання.
